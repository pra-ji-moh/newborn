Pay for the big model only when the work doesn't commute

Most AI queries fetch existing material: the facts can be gathered in any order and merged, so a small, cheap model is enough. Some need something new, or steps that must happen in order. Only those go to the big model. The router never decides by topic, so it also catches the odd case, like a media question that needs original work.

How it was tested

  • 3,000 real queries from five public datasets. Lookups: SciQ (science facts), WebQuestions (people, places, media) and Dolly-15k open questions. Needs the big model: GSM8K maths word problems and Dolly-15k creative writing.
  • Nobody labelled anything by hand. Whether a query needs the big model comes from the dataset it is in.
  • Tuned on one half, scored on the other. The rules were fixed before the test half was run. Dev and test scores agree: 90.1% and 90.3% routed right.
  • The router runs on this page, in your browser, in well under a millisecond. It is the same code that produced the numbers.

Not measured yet

  1. Answer quality. No model was called. The savings assume the small model answers lookups well enough; the next step is to run both models on these queries and grade the answers.
  2. About one in five "needs big" queries are sent small. Part of that is label noise: Dolly's creative-writing set includes plain fact questions such as "What is the most popular sport?". Part is real misses.
  3. Public datasets, not a customer's traffic. The mix here is 40% queries that need the big model. A real query log will have its own mix, and the savings move with it.
  4. No comparison with commercial routers yet. The baseline here is a plain topic router.
